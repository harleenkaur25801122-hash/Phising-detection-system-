# Sentry Scan — Phishing Detection (URL / Domain / QR / Batch)

An end-to-end phishing detection system combining:
- **Machine learning** (RandomForest on lexical/structural URL features)
- **Rule-based heuristics** (IP-in-URL, shorteners, suspicious keywords, high-risk TLDs, typosquatting)
- **Domain intelligence** (WHOIS age, DNS resolution, MX records — when network access is available)
- **QR code decoding** (OpenCV) → feeds extracted URL into the same analysis pipeline
- **Batch scanning** of CSV/TXT files (many URLs at once)
- **Automatic scan history** (SQLite) for every URL / QR / batch / domain scan
- **Statistics dashboard** — totals, verdict breakdown, 7-day activity chart, recent activity
- **Threat intelligence** — SSL certificate status, domain age, VirusTotal lookup, redirect chain, and an overall Low/Medium/High/Critical threat level

The original detection logic (`src/model/predict.py`, `src/features/*`,
`src/qr/qr_decoder.py`) is **unchanged** — everything above is additive, layered
on top in `src/history_db.py`, `src/threat_intel.py`, and new routes in `src/app.py`.

## Quick Start

```bash
pip install -r requirements.txt

# 1. Generate the training dataset (synthetic — see note below)
python data/generate_dataset.py

# 2. Train the model
python src/model/train.py

# 3. Run the web app
python src/app.py
# open http://localhost:5000
```

### Optional: enable live VirusTotal lookups

The Threat Intelligence panel works without any extra setup (SSL check and
redirect tracing use only the standard library + `requests`). VirusTotal
lookups are optional — get a free key at virustotal.com, then:

```bash
export VIRUSTOTAL_API_KEY="your_key_here"   # Windows: set VIRUSTOTAL_API_KEY=your_key_here
python src/app.py
```

Without a key, the panel simply shows "API key not set" and every other
feature keeps working normally.

## API Endpoints

| Method | Endpoint                          | Body / Params                                  |
|--------|------------------------------------|-------------------------------------------------|
| POST   | `/api/analyze/url`                | JSON `{"url": "http://..."}`                    |
| GET    | `/api/analyze/domain/<domain>`    | path param                                       |
| POST   | `/api/analyze/qr`                 | multipart file upload (`file`, an image)         |
| POST   | `/api/analyze/batch`              | multipart file upload (`file`, a `.csv`/`.txt`)  |
| GET    | `/api/history`                    | query: `limit`, `type`, `verdict`, `search`      |
| DELETE | `/api/history`                    | clears all scan history                          |
| DELETE | `/api/history/<id>`               | deletes a single scan record                     |
| GET    | `/api/stats`                      | dashboard totals + chart-ready data              |

`/api/analyze/batch` accepts a `.txt` file with one URL per line, or a `.csv`
with a `url` / `urls` / `link` / `website` column (falls back to the first
column). Up to 300 URLs per upload; each row is scanned with the same ML +
rule engine and logged to history, but skips the slower network-bound threat
intel checks (SSL/redirects/VirusTotal) to stay fast.

Example:
```bash
curl -X POST http://localhost:5000/api/analyze/url \
  -H "Content-Type: application/json" \
  -d '{"url": "http://paypa1-secure-login.tk/verify"}'
```

Response:
```json
{
  "verdict": "phishing",
  "confidence": 1.0,
  "ml_score": 0.99,
  "reasons": [
    "URL contains multiple credential/urgency-related keywords",
    "Domain name looks randomly generated (high entropy)",
    "Domain uses a top-level domain often associated with abuse"
  ]
}
```

## ⚠️ Important: Synthetic Training Data

This project ships with `data/generate_dataset.py`, which **synthetically generates**
phishing-like and legitimate-like URLs following known patterns (typosquatting,
raw IPs, shorteners, suspicious keywords, high-risk TLDs). This lets the entire
pipeline run and train **offline**, but it is not real-world data, and the model
hits 100% accuracy on it because the synthetic patterns are cleanly separable.

**For a production-grade model, replace it with real data:**
- Phishing URLs: [PhishTank](https://www.phishtank.com/) or [OpenPhish](https://openphish.com/) (free feeds)
- Legitimate URLs: [Tranco top-1M](https://tranco-list.eu/) or Common Crawl
- Re-run `train.py` pointed at the new CSV (same `url,label` schema)

Expect real-world accuracy to be lower and to require more careful feature
engineering, class balancing, and periodic retraining as phishing patterns evolve.

## Domain Intelligence Notes

`domain_features.py` uses `python-whois` and `dnspython` for WHOIS age and MX
record checks. These require:
1. The packages installed (`pip install python-whois dnspython`)
2. Live internet access at runtime

If either is unavailable, the functions **fail gracefully** (return `None`)
rather than crashing — the rest of the pipeline (URL features + ML model +
typosquatting, which is fully offline) still produces a verdict.

## QR Code Notes

Decoding uses OpenCV's built-in `cv2.QRCodeDetector` — no extra dependency
needed. To generate test QR images, either:
```python
import cv2
encoder = cv2.QRCodeEncoder.create()
img = encoder.encode("https://example.com")
cv2.imwrite("test.png", img)   # remember to scale up + add a white border
```
or `pip install qrcode` and use `qrcode.make(...)`.

## Threat Intelligence Notes

`threat_intel.py` adds three network-bound checks on top of the existing
verdict, purely for display — they never change the ML score or verdict:
- **SSL**: connects on port 443 and inspects the certificate (issuer, expiry)
- **Redirects**: follows the URL's redirect chain and flags domain changes
- **VirusTotal**: reads back an existing report for the URL (v3 API) if
  `VIRUSTOTAL_API_KEY` is set — it does not submit new scans, to stay within
  free-tier quotas

Each check fails gracefully (returns a clear "unavailable"/"not configured"
status) if there's no internet access or no API key, so the app always keeps
working end-to-end offline — same philosophy as the existing WHOIS/DNS checks.

## Scan History & Dashboard Notes

Every scan (URL, domain, QR, or batch row) is written to `data/history.db`
(SQLite, created automatically on first run) with its verdict, risk score,
threat level, and timestamp. The History page supports filtering by type/
verdict, free-text search, per-row delete, and clear-all. The Dashboard page
reads the same table to show totals, a verdict breakdown donut chart, a
7-day activity bar chart, and a recent-activity feed.
